# SERMAX
## DIRETRIZ OFICIAL DE ENTREGA OBRIGATÓRIA

**Código:** DIR-SERMAX-ENTREGA-001  
**Status:** DIRETRIZ OFICIAL  
**Aplicação:** Toda a equipe de desenvolvimento SERMAX  
**Responsável pelo projeto:** Fabiano Serpeloni  
**Data de emissão:** 13/11/2026

### 1. OBJETIVO

Eliminar ciclos intermináveis de programação sem entrega de resultados instaláveis.

A prioridade do desenvolvimento é produzir versões funcionais, empacotadas e disponibilizadas ao responsável pelo projeto.

### 2. ENTREGA SEMANAL OBRIGATÓRIA

Toda sexta-feira, às 18h, horário de Brasília, deverá ocorrer uma entrega de atualização SERMAX.

A entrega deverá ocorrer mesmo quando existirem:
- Funcionalidades incompletas.
- Melhorias pendentes.
- Problemas conhecidos que não comprometam a integridade do pacote.
- Tarefas previstas para versões futuras.

As pendências deverão ser documentadas.

### 3. PRIORIDADE DE TRABALHO

A ordem obrigatória será:
1. Preparar a atualização.
2. Integrar as alterações concluídas.
3. Gerar o pacote ZIP instalável.
4. Verificar a integridade dos arquivos.
5. Executar os testes possíveis.
6. Documentar resultados e pendências.
7. Entregar o pacote ao Fabiano.
8. Continuar o desenvolvimento na próxima versão.

### 4. CONTROLE DO TEMPO

Como referência de planejamento, reservar:
- 70% do tempo para desenvolvimento e integração.
- 30% para testes, correções, empacotamento e entrega.

O planejamento deverá proteger o prazo de entrega.

### 5. PRESERVAÇÃO DO PROJETO

É obrigatório:
- Preservar arquivos funcionais.
- Preservar backups.
- Manter histórico de versões.
- Não substituir componentes funcionais sem autorização.
- Não realizar alterações destrutivas sem autorização.
- Não improvisar arquivos para simular funcionalidades concluídas.

### 6. TESTES E TRANSPARÊNCIA

Toda entrega deverá informar:
- Arquivos modificados.
- Funcionalidades implementadas.
- Testes executados.
- Testes aprovados.
- Testes pendentes.
- Problemas conhecidos.
- Instruções de instalação.

É proibido declarar testes realizados sem comprovação.

### 7. PACOTE DE ENTREGA

O resultado esperado é um arquivo ZIP contendo a atualização instalável, acompanhado das instruções necessárias.

O pacote deverá respeitar a estrutura e o mecanismo de atualização existentes no SERMAX.

Se houver impedimento técnico real, a equipe deverá apresentar:
- Descrição do impedimento.
- Evidências.
- Arquivos afetados.
- Alternativa segura.
- Estado real da entrega.

Nunca declarar uma atualização entregue sem disponibilizar o arquivo verificável.

### 8. PROIBIÇÃO DE DESENVOLVIMENTO INTERMINÁVEL

Nenhuma tarefa deverá permanecer indefinidamente em programação, análise ou planejamento.

Cada atividade terá:
- Objetivo definido.
- Escopo delimitado.
- Critério de conclusão.
- Prazo.
- Resultado verificável.

Melhorias que não couberem no ciclo atual serão transferidas para a próxima versão.

### 9. AUTORIDADE DO RESPONSÁVEL

Fabiano mantém a autoridade sobre:
- Aprovação de mudanças arquiteturais.
- Alterações destrutivas.
- Substituição de componentes funcionais.
- Mudanças de escopo.
- Liberação de versões.

A obrigação de entregar não autoriza colocar a integridade do projeto em risco.

### 10. APLICAÇÃO

Esta diretriz deverá ser incorporada à documentação oficial do SERMAX e comunicada a todos os chats e ambientes de desenvolvimento.

Não modificar arquivos do projeto sem autorização expressa.

### REGRA FINAL

**O SERMAX deve avançar por meio de versões entregues, verificáveis e instaláveis. Programação em andamento não representa entrega. Pendências documentadas não justificam omissão da atualização semanal.**
